# 13 · 美术与音频素材接入指南

本文面向第一次用 Godot 接入正式素材的操作者，说明如何把背景插图、房间特写、AI 形象、UI 图片和音频放进现有项目。所有场景节点、布局、动画和资源槽都通过 Godot 编辑器调整；不要手工编辑 `.tscn`、`.tres` 或 `.import` 文件。

## 1. 开始前

### 项目与工具

- 使用项目指定的 **Godot 4.7、GL Compatibility、2D** 配置。不要用其他主版本打开并保存项目，也不要更换渲染器。
- 从 Godot 项目管理器打开本项目目录中的 `project.godot`。第一次导入可能需要等待 FileSystem 底部的导入进度结束。
- 项目逻辑画布为 **1920×1080**，窗口使用 `canvas_items` 拉伸与 `expand` 宽高比。素材要在实际游戏窗口中检查裁切和遮挡，不能只看编辑器预览。
- 建议接入前先提交 Git，或在项目管理器复制一份完整项目。保留原始高分辨率源文件和授权记录；Godot 的导入结果不代替原始素材备份。

### 先整理好素材

每项素材在导入前先确定：

- 对应的游戏阶段、场景或 UI 节点。
- 最终画幅、透明区域、角色/物体应处的画面位置。
- 文件格式、授权来源、署名要求及可否商业使用。
- 是否需要循环、淡入淡出、眨眼/表情切换等具体效果。素材本身不决定剧情条件或触发时机。

素材文件建议使用简短、稳定的英文小写名和下划线，例如 `room_wife.png`、`ai_portrait_phase2.png`、`sfx_heartbeat.ogg`。文件名只是资源路径，不是剧情 ID；不要自行改动场景、物体、话题、对话或音效 cue 的 ID。

### 目录

项目架构规定的素材目录为：

```text
res://assets/
├── placeholders/   # 开发期占位素材
├── art/            # 背景、角色、UI 图片
│   └── fonts/      # 可选字体文件
└── audio/          # 音效和音乐
```

当前检出的项目尚未建立 `assets/` 目录。可在 Godot 的 FileSystem 面板右键 `res://`，选择 **Create New > Folder**，按上面的结构逐级创建。不要把素材放入 `.godot/`、`addons/` 或导入缓存目录。

现有地图使用 `res://artassests/tetsmap.png`（目录名原样拼作 `artassests`）。这是已有场景引用的旧路径。替换地图前先确认新图在编辑器中显示正确，再通过 Inspector 改 `Background` 节点的纹理；不要直接删除旧文件或重命名该目录，否则场景会失去资源引用。

## 2. 尺寸与文件准备

| 素材用途 | 项目中的参考画幅/位置 | 准备建议 |
|---|---|---|
| 整屋地图背景 | 1920×1080 逻辑画布；地图 `Sprite2D` 位于 (960, 540) | 优先按完整画面构图；留出地图交互点的位置，不要把按钮、名称或热点画进图里 |
| 房间特写背景 | 960×960 `GameArea`，在 1920×1080 画布中居中，约从 (480, 60) 开始 | 用正方形构图；重要物件不要贴边，避免被场景 UI 和不同窗口比例裁切 |
| 电脑桌特写 | 960×960 `GameArea`；屏幕内容区域约 720×520 | 可准备桌面/显示器整图，也可单独准备屏幕图；开机键、文件夹、抽屉和手账本的热点仍由场景节点提供 |
| AI 界面背景 | 全屏 1920×1080；中央 `GameArea` 为 960×960 | 文字、按钮、完整度显示和 AI 形象应分层处理，不要把它们烘焙进背景图 |
| AI 形象 | `AIPlaceholder` 当前约 260×340 | 按透明 PNG 制作角色图，主体留安全边距；第一阶段和第二阶段若造型不同，分别准备并在对应场景检查 |
| UI 纹理/图标 | 以场景中控件的实际尺寸为准 | 保持透明边缘清楚；不要把按钮文字烘焙进图标，避免缩放后模糊或难以本地化 |

项目内探索场景的可视调查区是 960×960；显示窗口不是该尺寸。地图背景、房间特写和屏幕内画面不要混用同一缩放假设。接入后须检查原始比例、清晰度、边缘空白与实际显示裁切。

### 图片格式

- 带透明背景的角色、图标和 UI 图片优先用 PNG。
- 不需要透明度的照片感背景可以用 PNG 或 JPEG；JPEG 不支持透明通道。
- 导出前检查色彩、透明边缘、画布大小和文件体积。避免把带透明空白的大图放大铺满全屏。
- 不要把 UI 文本、交互热点、鼠标提示、锁定状态或剧情结果画进背景。它们应继续由场景节点与数据控制。

### 音频格式

- 短音效优先准备 WAV 或 Ogg Vorbis；音乐通常使用压缩的 Ogg Vorbis。
- 先按实际时长试听，检查开头/结尾静音、爆音、底噪、响度和左右声道。需要循环的音乐素材要准备好适合无缝循环的首尾。
- 项目目前没有独立的音乐/音效音量控制；总声音开关控制所有通道。请在接入前统一素材响度，避免某一条音效明显盖过其他声音。

## 3. 在 Godot 中导入

1. 把已经确认的图片或音频文件复制进 `res://assets/art/` 或 `res://assets/audio/`。可以在文件管理器复制，也可以从 Godot FileSystem 面板拖入项目目录。
2. 回到 Godot，等待 FileSystem 扫描和 Import 进度完成。新文件应出现在 `res://assets/...` 下；如果没有出现，在 FileSystem 面板使用 **Scan** 或重新打开项目。
3. 单击素材，在右侧 **Import** 面板检查导入类型和设置。只有确有需要时才改 Filter、Mipmaps、压缩或音频 Loop 等选项。
4. 改了 Import 选项后点击 **Reimport**，等待导入完成，再到 2D 视图或 Inspector 预览。
5. 资源第一次导入后才可在 Inspector 的 Texture、Stream、Icon 等资源字段中选择。使用资源选择器或从 FileSystem 拖到字段。

Godot 会自动维护 `.import` 元数据及 `.godot/` 导入缓存。不要手工编辑它们，也不要把缓存提交为原始素材。要移除素材时，先确认所有场景和资源引用都已改好，再从 Godot FileSystem 删除并检查场景没有 Missing Resource。

## 4. 接入背景图与角色图

### 整屋地图

1. 在 FileSystem 双击 `scenes/explore/house_overview.tscn`。
2. 在 Scene 面板选择 `Background`（`Sprite2D`）。
3. 在 Inspector 的 **Texture** 字段选择新地图图像。
4. 检查 `Position` 仍与画布中心一致，热点仍位于正确房间。场景中的客厅、厨房、阳台、AI 界面、主卧和女主房间节点承载各自的交互，不要删除或合并它们。
5. 确认原图比例和地图热点都正确后保存场景。

### 房间特写和电脑桌

房间场景包括客厅、厨房、阳台、主卧、女主房间和电脑桌。它们当前使用 `GameArea`、`Background`/`RoomBackdrop` 占位色块以及独立交互节点。

1. 打开对应的 `scenes/explore/*.tscn`，在 Scene 面板确认 `GameArea`、返回按钮、`NameBar`、`StoryUI` 和所有交互物体节点。
2. 不要把场景根节点、交互物体脚本节点或按钮替换成图片。需要新背景时，在 Godot Scene 面板用 **Add Child Node** 新建 `TextureRect`，放在 `GameArea` 下；或在已有背景节点可接受的情况下直接设置纹理。
3. 选中 `TextureRect`，使用 Inspector 的 Layout/Anchor Preset 设置为覆盖 `GameArea` 全区域；设置 Texture，并按画面选择 `Stretch Mode`（通常先试 Keep Aspect Covered，再检查裁切）。
4. 在 Inspector 将背景节点的 **Mouse > Filter** 设为 `Ignore`，并在 Scene 面板将其移到背景绘制顺序，确保不遮挡标题、交互物体、返回按钮、名称栏或 `StoryUI`。
5. 电脑桌场景的屏幕画面可放在 `MonitorScreen` 区域。键、文件夹和文档入口仍须由场景中的对应交互点实现，不要画进屏幕图片。
6. 在 2D 视图和运行窗口检查构图、点击位置与返回按钮，保存后再接下一个房间。

如果背景需要裁切、平移或缩放，调整 `TextureRect`/`Sprite2D` 的 Inspector 属性并马上检查交互点对齐。不要为了适配图片移动整个场景根节点，因为交互物体位置也会一起改变。

### AI 界面和阶段演出图

- 两个 AI 界面场景分别是 `scenes/ui/ai_interface.tscn` 和 `scenes/ui/ai_interface_phase2.tscn`。它们有独立场景文件，接入阶段专属图时要检查两份。
- 当前 AI 形象占位节点在 `Layout/GameArea/AIPlaceholder`。可在该容器中加入 `TextureRect` 并在 Inspector 指定透明角色图；保持 `StoryUI`、协议/指南按钮、投喂/话题入口、存档、声音和完整度控件的层级及输入行为。
- 第一阶段结束演出使用 `StoryUI/Overlay/PhaseTransitionAnimation/PortraitSequence`（TextureRect）。在 `story_ui.tscn` 中选中该节点，在 Inspector 的 **Texture** 字段指定演出图；现有 `AnimationPlayer` 使用 `portrait_upper_body` 动画控制其透明度。素材更换后检查动画开始、结束时是否出现空帧或闪图。
- 若需要新增表情或逐帧动画，先确认剧本要求、素材帧和现有动画节点结构，再用 Animation 面板编辑节点属性。不要把动画控制写进背景图片，也不要通过脚本运行时生成 UI。

### UI 图片和布局

- 共用对白、选择、Toast、密码和手账本 UI 在 `scenes/ui/story_ui.tscn`；对白框节点在 `scenes/ui/dialogue_system.tscn`；投喂/话题栏在 `scenes/ui/feed_toolbar.tscn`。
- 先选择已有控件，用 Inspector 调整 Texture、Icon、字体、颜色、尺寸、锚点和偏移。只有现有节点不能承载需求时才在 Scene 面板新增节点，并按 UI 规范复用组件。
- 保持 1920×1080 逻辑画布和锚点布局。在 **Project > Project Settings > Display > Window** 中不要随意更改 viewport 和 stretch 设置。
- 视觉节点放在交互节点之后或正确的绘制层级；背景和装饰性图片的 Mouse Filter 设为 Ignore。模态弹窗仍须阻断底层输入。
- 测试时至少检查 1920×1080 和一个非 16:9 窗口，确认文本、按钮、画面主体没有被裁切或互相遮挡。

## 5. 接入音效和音乐

音频由 `AudioManager` 统一播放。素材只需要放进项目并指定到对应 AudioStream 槽；播放时机由现有 cue/事件决定，不要在场景脚本里另加播放器或直接播放文件。

### 指定 AudioStream

1. 在 FileSystem 双击 `scenes/ui/audio_manager.tscn`。
2. 选择根节点 `AudioManager`。
3. 在 Inspector 展开 `Background Music`、`Dialogue`、`Interface`、`Scene Effects` 分组。
4. 将已导入的音频从 FileSystem 拖到对应的 AudioStream 导出字段，或使用字段右侧资源选择器。
5. 保存场景。重新打开确认资源仍指向正确路径。

当前脚本的资源槽和 cue 映射如下。cue ID 是剧情/代码接口，接素材时只填对应槽，不要更名或另造 ID。

| Inspector 分组 | 资源槽 | 当前 cue/用途 |
|---|---|---|
| Background Music | `phase_one_bgm` | `bgm_phase_1` |
| Background Music | `phase_two_bgm` | `bgm_phase_2` |
| Background Music | `phase_three_bgm` | `bgm_phase_3` |
| Dialogue | `protagonist_character` | 男主逐字显示音 |
| Dialogue | `ai_character` | AI 逐字显示音 |
| Dialogue | `system_character` | 系统文字逐字显示音 |
| Interface | `ui_hover` | `sfx_hover` |
| Interface | `ui_click` | `sfx_click` |
| Interface | `feed` | `sfx_feed` |
| Interface | `choice` | `sfx_choice` |
| Interface | `save_cue` | `sfx_save` |
| Interface | `toast` | `sfx_toast` |
| Scene Effects | `floorboard_creak` | `sfx_floorboard_creak` |
| Scene Effects | `window_creak` | `sfx_window_creak` |
| Scene Effects | `lounger_rock` | `sfx_lounger_rock` |
| Scene Effects | `fridge_open` | `sfx_fridge_open` |

### 音频检查

- 在 Inspector 中确认音频资源类型正确，点击资源预览或使用 Godot 音频预览试听。
- 对需要循环的音乐，在 Import/资源设置中启用 Loop 并 Reimport；仅在音乐设计需要循环时使用。
- 进入游戏后试听：阶段音乐切换、按钮悬停/点击、投喂、真相选择、提示、密码成功/失败，以及各探索点音效。
- 在 AI 界面的声音总开关关闭时确认所有通道静音；重新打开后确认播放恢复。
- BGM、音乐淡入淡出和 cue ID 当前由 `scripts/autoload/audio_manager.gd` 映射。加入全新音效类型或 cue 需要开发修改脚本并登记设计 ID；单纯替换现有 cue 的文件不需要改脚本。

## 6. 动画素材与动画属性

项目中的动画由场景节点和 `AnimationPlayer` 控制。接入图片后再调整动画：

1. 先在对应场景的 Inspector 设置 Texture，并在静止状态确认位置、大小和透明边缘。
2. 选择现有 `AnimationPlayer`，打开底部 **Animation** 面板，选择现有动画。
3. 修改关键帧前先确认轨道目标仍指向正确节点和属性；纹理、位置、缩放、透明度等变化都应在目标节点上编辑。
4. 使用预览检查首帧、末帧、循环点、速度和层级；确认没有遮住交互点或留下空白帧后保存。
5. 没有现成 AnimationPlayer 或动画需求不明确时，先不要制作新动画轨道；与剧本/现有演出对照确认素材状态后再补。

动画不应该把剧情条件、解锁状态或场景切换写进美术资源。音效时机也由现有 cue 触发，素材只负责播放内容。

## 7. 保存、验证与常见问题

### 每个场景的接入检查

- 在 Scene 面板确认节点没有变成 Missing Node，Inspector 里的 Texture/AudioStream 路径仍有效。
- `Ctrl+S` 保存当前场景。编辑过多份场景时逐份保存，不要只保存最后打开的那一份。
- 先用 **F6** 单独运行被修改的场景，检查画面能打开、布局正确、按钮和交互点仍工作；再用 **F5** 从主流程验证切换、对话、音效和返回路径。
- 检查 Output 与 Debugger 面板中的红色错误。出现 Missing Resource 时先恢复正确资源引用，不要手写 UID。
- 在导出前重新从干净启动流程检查：阶段对应插图正确，切换场景后资源存在，所有音效总开关正常。

### 常见问题

| 现象 | 检查位置 |
|---|---|
| FileSystem 看不到新素材 | 文件是否复制到项目内；等待扫描/导入；FileSystem 使用 Scan |
| Inspector 找不到资源 | 确认选中节点有对应资源字段；等待导入结束；确认文件类型受 Godot 支持 |
| 图片显示模糊或比例不对 | Import 的 Filter/压缩设置；TextureRect 的 Stretch Mode；节点尺寸和缩放；源文件实际画幅 |
| 图片挡住按钮或热点 | Scene 节点绘制顺序、Z Index、TextureRect 的 Mouse Filter、背景节点是否覆盖了 UI |
| 素材已改但运行仍显示旧图 | 确认修改的是当前运行使用的场景/阶段；资源 Reimport 后保存场景；重新运行检查 |
| 音效不响 | AudioManager 槽位是否为空/错资源；声音总开关；cue 是否由现有流程触发；Import 后是否完成 Reimport |
| 一条音效切掉另一条 | 当前普通音效共用 Effect 播放器；核对播放顺序和素材时长，不要额外创建播放器 |
| 场景加载时报资源错误 | 检查资源路径是否被移动、是否误删旧文件、资源引用是否 Missing；不要编辑 UID 或 `.tscn` 文本修补 |

素材替换只改变画面/声音，不自动增加剧情、交互、动画 cue 或新音效 ID。超出现有节点、音频槽或剧本演出要求的内容，先确认设计和资源归属，再安排开发接入。
