# 《涌现》UI 与交互区域编辑指南

本文按 Godot 编辑器中的场景树说明如何调整 UI 位置、尺寸和交互区域。游戏画面区域统一为 960×960；多数场景根节点按 1920×1080 编辑，游戏画面左上角为根节点坐标 (480, 60)。

## 先确认编辑坐标

1. 在 Godot 文件系统面板打开对应 `.tscn`，双击进入场景。
2. 切到 2D 视图，在场景树选中 `GameArea`。它是实际显示游戏图片的 `TextureRect`，通常位置是 (480, 60)，尺寸是 960×960。
3. `GameArea` 的子节点坐标相对于图片左上角计算，不是相对于整个 1920×1080 游戏窗口。拖动交互按钮时，观察 Inspector 的 `Transform > Position` 和 `Layout > Size`。
4. 编辑器中的白色游戏画面定位参考层只用于编辑，不是游戏里的背景；不要把它当成实际图片或交互区域。
5. 调整后保存场景，运行对应场景检查实际位置。交互点目前是 50×50、半透明蓝色按钮；它们既是可见判定区域，也是玩家点击位置。

## 通用 UI 与场景专属 UI

### 多场景共用

| 功能 | 场景树位置 / 脚本 | 调整方式 |
|---|---|---|
| 对话框 | `StoryUI/Overlay/DialogueSystem`，定义于 `scenes/ui/dialogue_system.tscn` | 选中 `ProtagonistDialogue`、`AIDialogue` 或 `SystemDialogue` 调整框的位置和尺寸。文字节点在各自的 `Text` 下；四边各 30 px 的内边距由 `scripts/ui/dialogue_system.gd` 创建的 `TextMargins` 控制。 |
| 投喂、话题按钮与列表 | `StoryUI/Overlay/FeedToolbar`，定义于 `scenes/ui/feed_toolbar.tscn` | 调整 `Toolbar`、`FeedButton`、`TopicButton`，以及 `FeedPanel`、`TopicPanel` 中的容器布局。它只在 AI 培养界面显示投喂按钮；第三阶段客厅对话界面仅显示话题按钮。 |
| 音效开关 | `StoryUI/Overlay/SoundButton`，位于 `scenes/ui/story_ui.tscn` | 调整 `SoundButton` 的位置和尺寸；文字 `SoundLabel` 显示“音效：开/关”。它与存档按钮位于游戏画面外侧 UI 区。 |
| 存档 | `StoryUI/Overlay` 下运行时加入 `global_save_button.gd` | 当前按钮由 `scripts/ui/story_ui.gd` 创建，位置/尺寸在 `scripts/ui/global_save_button.gd` 的 `_ready()` 中设置。只有点击它才保存进度。改位置需改这个脚本；所有包含 StoryUI 的场景都会共用。 |
| 通用提示浮层 | `StoryUI/Overlay/Toast` | 调整 `Toast` 的矩形和字体属性。获得话题、内容等提示由事件发出，不要把提示改成独立全屏 UI。 |
| 全屏文本、选择、密码/手账面板、黑屏转场 | `StoryUI/Overlay/Reader`、`Choice`、`PuzzlePanel`、`DiaryPanel`、`Fade` | 在 `scenes/ui/story_ui.tscn` 调整面板及其子节点。剧情选择 UI 的按钮、文案及显示条件由脚本控制；这里只改视觉位置和尺寸。 |

这些 UI 的“共用”指使用同一个组件或脚本定义，不代表每个画面都显示所有控件。场景切换时由组件按当前场景和模态状态决定显隐。不要在单个房间场景里再复制一份对话、音效或存档控件。

### 场景专属

| 场景 / 文件 | 可调整内容 |
|---|---|
| 开始界面 `scenes/ui/start_screen.tscn` | 标题画面、开场逐帧动画和点击范围。开场图像及动画节奏在 `scripts/ui/start_screen.gd`。 |
| 第一、二阶段 AI 界面 `scenes/ui/ai_interface.tscn`、`ai_interface_phase2.tscn` | 培养界面底图及该场景专用控件；对话、投喂、话题、音效和存档仍由共用 StoryUI 提供。 |
| 第一、二阶段房间/特写 `scenes/explore/*.tscn` | 图片在 `GameArea`；交互点是 `GameArea` 下的按钮，例如 `TVHitArea` 或具体物体命名的节点。调整按钮的 `Position` 即移动判定区，调整 `Size` 即改变判定区尺寸。不要调整其外层 `GameArea` 来代替移动交互点。 |
| 第三阶段单独特写 `scenes/explore/phase3_*_closeup.tscn` | 每个特写有自己的 `GameArea` 和 `HeroineInteraction`。直接在对应场景里选中蓝色按钮拖动；改图时仍通过游戏图片目录/场景中的 `GameArea.texture`。女主在不同特写中的位置互不影响。 |
| 第三阶段剧情演出 `Act3View` | 由 `scripts/ui/act3_view.gd` 在运行时创建，用于 CG、剧情对话推进、选项和蓝色交互按钮；它不是每张 CG 的独立场景。当前交互按钮默认位置、电脑/抽屉等特例位置在该脚本中设置。需要逐场景可拖拽的位置时，应由剧情场景提供独立命名的交互区域，避免只改统一默认值。 |
| 真结局最终电脑/抽屉调查 `scenes/explore/phase3_true_ending_computer.tscn` | 这是独立于普通特写的场景。选中 `GameArea/DrawerInteraction` 拖动或在 Inspector 改位置和尺寸；此按钮只负责打开密码面板。 |

## 存档、音效、对话和投喂的常用操作

### 存档按钮

存档按钮是所有 StoryUI 场景共用的运行时节点，位置和尺寸在 `scripts/ui/global_save_button.gd` 设置。调整 `position`、`size` 和 `custom_minimum_size`；不要在每个场景各加一个存档按钮。进度只在点击存档按钮时写入，退出、切后台、切换场景及剧情推进不会自动保存。通关标记单独记录，用于下次点击开始时显示“继续/新故事”；选择新故事会清除进度文件和通关标记。

### 音效开关

在 `scenes/ui/story_ui.tscn` 选中 `Overlay/SoundButton` 调整外框位置和尺寸；选中其子节点 `SoundLabel` 调整“音效：开/关”的文字布局。静音行为由 `StoryUI` 转发给 `AudioManager`，不要为了移动按钮改音频播放脚本。

### 对话框

在 `scenes/ui/dialogue_system.tscn` 选择说话人对应面板：男主 `ProtagonistDialogue`、AI `AIDialogue`、旁白/系统 `SystemDialogue`。先调 PanelContainer 的矩形，再确认其内 `Text` 的换行、字号和可用空间。脚本会把文字放进 `TextMargins` 并固定四边 30 px 间距；若要改变边距，改 `scripts/ui/dialogue_system.gd` 的 `_add_text_margins()`，这会影响所有对话框。

### 投喂与话题

按钮本体和列表布局在 `scenes/ui/feed_toolbar.tscn`。具体条目来自数据，不需要为每条话题单独创建新按钮。调节列表时选 `FeedPanel` / `TopicPanel` 中的 `ScrollContainer`、`Items` 和关闭/全部投喂按钮。显示规则由 `scripts/ui/feed_toolbar.gd` 控制，调整视觉布局时不要改解锁或投喂判定。

## 交互点怎么调

1. 打开目标特写 `.tscn`，在场景树展开 `GameArea`。
2. 选择相应的蓝色 `Button`，例如 `HeroineInteraction`、`ComputerInteraction`、`DrawerInteraction` 或物体名对应的交互点。
3. 在 2D 视图拖动按钮，或在 Inspector 修改 `Transform > Position`；修改 `Layout > Size` 可改变点击区域。按钮默认 50×50，颜色来自半透明蓝色 StyleBox。
4. 确认这个节点仍在 `GameArea` 之下，保留原节点名、脚本连接/信号和 `preserve_button_background` 元数据。不要用可见大图遮住区域，也不要删掉旧按钮后重新命名成不匹配的 ID。
5. 保存并运行对应场景，确认按钮只覆盖目标物体，弹窗打开时底层区域不能响应。

第一、二阶段特写的点位分别保存在各自 `.tscn`；第三阶段每个 `phase3_*_closeup.tscn` 也各有自己的女主点位。改某个场景时，不要改另一个场景的同名按钮。

## 真结局女主房间：独立场景要求

真结局结尾在电脑与抽屉调查之前会再次进入女主房间。该处不应继续复用普通第三阶段女主房间的场景/交互点。单独创建 `scenes/explore/phase3_true_ending_wife_room.tscn`，场景树建议如下：

```text
Phase3TrueEndingWifeRoom (Control, 1920x1080)
├── Background (ColorRect, 全屏黑色)
├── GameArea (TextureRect, 位置 480,60，尺寸 960x960)
│   └── ComputerInteraction (Button, 50x50，半透明蓝色)
└── StoryUI (实例化 scenes/ui/story_ui.tscn)
```

在 Godot 编辑器中通过“场景 > 新建场景”建立该场景；根节点用 `Control`，将图片放入 `GameArea`，并在其下新建 `Button`，命名必须为 `ComputerInteraction`。把按钮拖到真结局房间图片中的电脑位置，保留半透明蓝色样式。将 `StoryUI` 场景实例加到根节点，使其具有与其他阶段三场景一致的共用对话、音效和存档 UI。不要复制 `phase3_wife_room_closeup.tscn` 后继续共用同一组交互点；新场景内的按钮位置必须独立保存。

新场景建好后，真结局路线进入它时，路线控制需要读取该场景 `GameArea/ComputerInteraction` 的位置和尺寸；点击后再进入现有的 `phase3_true_ending_computer.tscn`。普通探索仍使用 `phase3_wife_room_closeup.tscn`，两处点位分别调整、互不影响。路线切换应只替换真结局调查对应的房间步骤，不能替换之前用于普通对话的女主房间步骤。

目前真结局电脑抽屉已经使用独立场景 `phase3_true_ending_computer.tscn`；女主房间本身仍需按上面的步骤单独创建并接入真结局路线。创建/接线完成后，在该新场景中单独运行检查，并分别验证普通房间与真结局房间点位不会互相覆盖。

## 修改后检查

- 运行场景，检查游戏画面外的音效/存档位置和 960×960 游戏画面内的交互点位置。
- 分别测试鼠标与手机触屏；按钮移动后应仍能点击。
- 打开全屏文本、密码面板或选择面板时，检查底层交互点不响应。
- 对话框确认文字没有贴边：上下左右各至少 30 px。
- 手动存档后推进剧情并退出，再启动继续时应恢复最近一次手动存档；通关标记在通关后保留，选择新故事后被清除。
