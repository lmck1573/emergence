# 06 · 剧情事件与条件系统

> 职责：统一条件求值、事件触发排序、效果执行。**这是全游戏最重要的底层系统**。
> 事件与条件**全部数据驱动**（events.json），禁止为任何单个剧情写专属判定代码。

## 1. 核心原则

1. **统一检查机制**：每当调查、投喂、话题、选择、解谜、阶段转换改变游戏状态，`GameState` 调用一次 `check_events()`。**禁止在各物体/对话内部散落判定逻辑**。
2. **统一条件结构**：所有条件都是 docs/02 §9 的封闭类型 + `all`/`any` 组合，一套求值器通吃。**禁止为某个事件另写一套判定**。
3. **效果也是封闭集合**（docs/02 §9），执行器统一实现，事件配置只引用。

## 2. 事件生命周期

```
[未触发] --状态变更--> 条件求值
    ├─ 不满足 → 保持未触发
    └─ 满足 → 入队（按 priority 降序）
播放中（锁定：期间不再消费队列、屏蔽玩家操作）
    → 依次执行 effects
    → 写入已完成状态
    → 再次 check_events()（效果可能解锁后续事件）
    → 自动存档
[已完成] once=true 的事件永不再触发；once=false 按 trigger 定义
```

## 3. 执行顺序（严格按需求文档 9.3）

1. 玩家操作完成。
2. 更新对应的调查/内容/投喂/选择状态。
3. `check_events()`：求值所有未完成事件。
4. 满足条件的事件按 `priority`（数值大者优先）排序入队。
5. **逐个串行播放**：同一时刻只允许一段剧情在演，禁止并发。
6. 事件结束写入完成状态。
7. 效果可能改变状态 → 回到第 3 步（级联，但同一轮内每事件只触发一次，防死循环）。
8. 队列清空后自动存档。

**多个事件同时满足**：按优先级顺序串行执行，绝不合并、绝不并发。本期事件优先级约定见 docs/story 两份清单的事件表。

## 5. 特殊规则

| 规则 | 说明 |
|---|---|
| 触发时机为"回到 AI 界面"的事件（如 event_ai_after_unlock） | 条件满足 ≠ 立即播放；`trigger: "on_enter_ai_interface"`，玩家进入 AI 界面时检查播放，播放后标记完成 |
| 阶段转换事件 | `advance_phase` 效果由阶段转换事件调用；转换流程（列表清空、完整度校正、区域开放）见 docs/07 §3 |
| 事件播放中存档 | 播放中途退出游戏：重进后该事件视为未完成，从事件开头重新播放（宁可重播，不可跳过） |
| 级联防护 | 单次 check_events 的级联深度上限 10 层，超限报错（配置循环引用的保险丝） |

## 6. 对外接口

| 接口 | 说明 |
|---|---|
| `check_events()` | GameState 在每次状态变更后调用 |
| `event_completed(event_id: String)` 信号 | 事件完成时发 |
| `is_event_completed(event_id: String) -> bool` | 条件求值用查询 |
