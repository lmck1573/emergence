# 00 · 项目总览与待定项

> 《涌现》项目最高层文档。所有系统文档与剧情数据文档服从本文件的决策记录。
>
> 本文档体系基于三份策划源文档整理：①《涌现》第一/二阶段剧本文案；②《涌现》程序需求文档 V1.0；③《涌现》完整 UI 需求整理。源文档冲突时，以本文件决策记录（策划最终裁决）为准。

## 1. 项目定位

- **类型**：点击式叙事探索游戏（参考《享受这家餐厅吧》的点击探索形式）
- **核心循环**：探索场景点击物体 → 获得话题/爱好/经历/作品/线索 → 在 AI 界面对话或投喂 → 事件系统按条件触发剧情 → 解锁新区域/新阶段
- **核心叙事机制**：男主通过选择"告诉 AI 什么 / 隐瞒什么"影响真相暴露度，进而影响后续剧情
- **结构**：剧情按阶段推进。本期实现第一阶段（本我雏形 0-40%）与第二阶段（自我成形 40-80%）。**不设 21 天倒计时、每日任务、结束当天机制（已删除）。**

## 2. 技术栈（锁定）

| 项 | 值 |
|---|---|
| 引擎 | Godot 4.7（GL Compatibility） |
| 语言 | 纯 GDScript 2.0（禁止 C#） |
| 维度 | 2D |
| 平台 | PC（Windows） |
| 逻辑分辨率 | 1920 × 1080，探索场景为 960 × 960 正方形，水平垂直居中（场景左上角约 (480, 60)） |
| 编辑器桥接 | godot_ai 插件（MCP over WebSocket） |
| 剧情数据 | `res://data/` 下 JSON 外部文件 |
| 开发链路 | Claude Code + DeepSeek，通过 godot_ai MCP 操控编辑器 |

## 3. 术语表

| 术语 | 定义 |
|---|---|
| 交互物体 | 场景里可以点击的东西（电视、冰箱、照片墙……），配置见 docs/03 |
| 内容碎片 | 调查/对话后获得的信息，分四种类型：爱好 / 经历 / 作品 / 线索 |
| 话题 | AI 对话界面的对话入口（不是碎片，不参与投喂） |
| 剧情事件 | 满足条件组合后触发的一段剧情（docs/06） |
| 解谜对象 | 需要额外操作完成的内容（docs/08），本期只有日期密码 |
| 投喂 | 玩家将内容碎片交给 AI 并播放对应回应的行为 |
| 调查 | 点击交互物体查看文本的行为（可重复，内容只发一次） |
| 真相暴露度 truth_revealed | 男主已向 AI 揭露真实信息的程度（整数点数，docs/07） |
| 人格完整度 | AI 人格的成长数值，全局百分比显示（docs/07） |
| 阶段 | 第一阶段（本我雏形 0-40%）、第二阶段（自我成形 40-80%）、第三阶段（超我涌现 80-100%，本期不实现） |

**状态区分（重要）**：「已调查」「已获得」「已使用（话题）」「已投喂」「已完成（事件/解谜）」是**五个不同状态**，禁止用单一"已完成"标记代替。

## 4. 决策记录（2026-10-15，策划最终裁决）

以下裁决为最终决定，开发时直接执行，不再讨论：

| # | 决策 |
|---|---|
| D01 | **剧本优先**：点击物体只发放剧本标注"获得"的直接内容；「一起看爱乐之城」「一起包饺子」两条经历分别在完成「电影」「她的口味」话题对话后发放 |
| D02 | 阳台躺椅 → 获得「经历：一起晒太阳」。需求文档 5.4 表格中"话题：写作"为笔误，第一阶段不存在该话题，不实现 |
| D03 | 主卧解锁条件 = 开场两份协议已读 + 客厅/厨房/阳台全部 11 个交互点完成（含二级操作）+ 全部 10 项可投喂内容已投喂 |
| D04 | 日期密码提示事件条件 = 已投喂「手账本」+「旅行」+「可爱的玩偶」+ 已完成话题「锁上的电脑」（即第二阶段开始可获得的所有可投喂内容全部投喂完） |
| D05 | 人格完整度：配置驱动增量（每个可投喂内容在 JSON 中配置增量），阶段转换时校正到阶段区间端点；UI 以全局百分比显示 |
| D06 | U 盘剧情"人格完整度已达 99%" = **阶段内进度 99%**（约 39.6%）；说出真相后阶段转换校正至 40% |
| D07 | 真相暴露度：整数点数制，初始 0，选「是」+1、选「否」+0；聊天记录投喂分支阈值 = `truth_revealed ≥ 1` |
| D08 | 开场两份协议各自记录已读状态，**两份都读过才解锁探索入口**（做成配置开关 `opening_required`） |
| D09 | 存档按钮：点击后立即保存并显示"已保存"反馈，无二次确认 |
| D10 | 社交帐号「我应该告诉她吗？」= 不可交互演出（红色滤镜 + UI 出现 + 玩家无法点击 + 3 秒后红色淹没屏幕 + UI 消失），不加真实按钮、不改真相暴露度 |
| D11 | 剧情数据用 JSON 外部文件（`res://data/`），schema 见 docs/02 |
| D12 | 开发总纲文件名 = `AGENTS.md`（项目根目录） |
| D13 | 开发期美术/音频全部用色块/静音占位，交互点可视化调试，素材后补不阻塞开发 |
| D14 | 话题「锁上的抽屉」剧本未提供对话内容：引擎默认行为 = 无对话配置的话题不显示在 AI 界面可选列表（已获得状态照常记录） |
| D15 | 密码输入发生在**电脑界面的上锁交互点**；密码解锁的是电脑（三个文件夹出现）。手账本最后一本保持上锁展示状态 |
| D16 | 导航层级：区域特写 → 整屋俯视图；电脑桌特写 → 女主房间特写；AI 界面 → 整屋俯视图。俯视图上设"电脑"交互区域，点击进入 AI 界面。左下角"退出到底图"按当前层级返回上一级，俯视图中隐藏该按钮 |
| D17 | 文本播放位置：男主独白 / 剧情叙述 / 调查文本 / 协议长文本 → **全屏文本 UI**（纯色底图）；与 AI 的对话（话题/投喂回应）→ **AI 界面**（含 AI 形象演出：眼睛动画、女主形象、表情变化） |
| D18 | 投喂列表（UI 文档裁决，覆盖程序需求文档 4.2 的状态显示方案）：只显示**当前阶段已收集、尚未投喂**的材料；投喂成功后从列表移除；阶段切换时列表清空（已投喂状态本身永久保留在存档中供事件条件判断） |
| D19 | 话题列表：只显示当前阶段已解锁话题；未解锁话题**不显示**（P13 默认取隐藏方案）；已解锁话题可反复点击反复对话，重复对话不重复发内容；阶段切换时列表清空 |
| D20 | 对话框 UI：男主台词 → **屏幕左下角**；女主（AI）台词与其他提示文本 → **屏幕右上角**（同一显示区域）。按说话者切换位置与样式，禁止互相覆盖；无头像、无立绘、无角色名称标签；男主与女主文本以字体/颜色/样式明显区分（具体风格见 P17 占位）；单句文本结束后按剧本流程自动消失或等待玩家点击推进 |
