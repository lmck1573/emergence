# 08 · 解谜系统 — 日期密码

> 职责：谜题的入口控制、输入判定、完成反馈与一次性发奖。**不做事件条件判定**——谜题只上报"完成"。
> 本期唯一谜题：手账本日期密码（puzzle_diary_password）。照片拼合/文件恢复为 P1 待定（P05），不实现。

## 1. 通用规则

| 规则 | 说明 |
|---|---|
| 谜题状态 | 锁定（unlock_event 未完成）→ 可解 → 已完成，三态持久化存档 |
| 锁定时 | 入口物体点击 → toast"暂时无法交互"（不弹谜题 UI） |
| 完成判定 | 统一由谜题组件执行，答案来自 puzzles.json |
| 错误反馈 | 显示错误提示，允许无限重试，无惩罚 |
| 成功结算 | **只结算一次**：播放成功反馈 + on_complete 效果；之后重进显示已完成状态，不再要求输入、不再发奖 |

## 2. puzzle_diary_password 详细规格（决策 D15）

```
玩家（电脑桌特写）点击手账本
  → 首次：播放独白（这里记录着她大学二年级以来的所有事件…游戏清单…）
  → 打开手账本阅读界面（diary_viewer）：显示日期+事件列表
  → 再次点击手账本（退出后再进）：不再播独白，直接进阅读界面
  → 点击电脑屏幕上的"上锁"交互点
  → 弹出四位数字轮盘锁（puzzle_wheel）
  → 输入 1224 → 成功
      → 播放解锁独白（*竟然真的打开了？……她又有什么可以瞒着我的呢？）
      → 电脑桌面出现三个文件夹交互点（games/social/bills）
      → 写入 puzzle_diary_password_completed = true，存档
  → 输入错误 → 错误提示，可重试
```

| 项 | 规格 |
|---|---|
| 答案 | `"1224"`（四位，逐位对照） |
| 密码含义（仅注释，不进 UI） | 12.24 = 她收到台式电脑的那天（手账本事件列表中有对应条目） |
| 输入 UI | 四位数字轮盘锁（puzzle_wheel.tscn），确认 / 取消按钮，错误提示区 |
| 手账本事件列表（diary_entries，展示数据，**不是五个独立剧情事件**） | 03.22 / 04.14 / 05.30 / 08.21 / 12.24 / 01.12 六条（含 05.30，剧本原文如此；需求文档 6.5 漏列 5.30，以剧本为准），逐字来自 docs/story |
| 上锁的手账本最后一本 | 保持上锁展示状态（D15：密码只解锁电脑） |
| 三个文件夹 | 出现即可点击，无额外条件（谜题完成本身就是出现条件） |

## 3. 对外接口

| 接口 | 说明 |
|---|---|
| `puzzle_completed(puzzle_id: String)` 信号 | 成功结算时发一次 |
| `is_puzzle_completed(puzzle_id: String) -> bool` | 查询 |
| `is_puzzle_unlocked(puzzle_id: String) -> bool` | 查询（unlock_event 完成态） |
