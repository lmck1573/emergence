# 04 · 内容碎片与投喂系统

> 职责：内容的获得/去重、投喂列表 UI、投喂流程与状态流转。**不做条件判定**——投喂完成只上报 `GameState`。

## 1. 内容分类（四类碎片 + 话题单独管理）

| 类型 | 用途 | 本期实例 |
|---|---|---|
| 爱好 hobby | 反映个人偏好，可投喂 | 看电影、甜品、晒太阳、旅行、可爱的玩偶、喜欢的游戏 |
| 经历 exp | 过去发生的事，可投喂 | 养昙花、早课的早餐时间、一起包饺子…… |
| 作品 work | 女主创作/保存的个人内容，可投喂 | U盘、手账本、删减的聊天记录 |
| 线索 clue | 揭示背景，**默认不可投喂** | 同居第一天、咖喱鸡排蛋包饭 |
| （话题 topic | AI 对话入口，**永不投喂**，docs/05） | 电影、U盘…… |

## 2. 投喂列表（决策 D18）

| 规则 | 说明 |
|---|---|
| 入口 | 左下角功能 UI"投喂"按钮（docs/12 §2） |
| 列表内容 | **当前阶段 + 已获得 + `feedable=true` + 未投喂** 的材料，四条件同时满足 |
| 隐藏规则 | 未获得不显示；不可投喂（线索）不显示；已投喂不显示（投喂后从列表移除） |
| 条目显示 | 材料名称 + 类型标记（图标占位为文字标签） |
| 阶段切换 | 列表清空，按新阶段重建；**已投喂状态永久保留在存档**（供事件条件判断，如 D03/D04） |
| 模态 | 打开期间底层禁点；关闭恢复进入前界面状态 |

## 3. 投喂流程（严格按序执行）

1. 玩家在列表点选一条材料。
2. 校验：已获得？→ 否则不显示（列表本来就不含）。
3. 校验：`feedable = true`？→ 否则不显示。
4. 校验：投喂前置条件（`feed_conditions`，可为空）满足？→ 不满足则 toast"暂时无法投喂"。
5. 校验：未投喂过？（列表已保证，双保险）。
6. **自动切入 AI 界面**，播放 `feed_dialogue`。
7. 对话（含可能的分支/选择）播完 → 写入已投喂状态 → 完整度累加 `completeness_bonus`（docs/07）。
8. `content_fed` 信号 → `GameState` → `check_events()`（docs/06）。
9. 自动存档。

**已投喂内容**：不可再次投喂（不在列表中）；如需回看回应，不做（本期无此需求，剧本未要求）。

## 4. 分支回应（聊天记录投喂，第二阶段）

`work_chat_records` 的 `feed_dialogue` 为分支对话：

| 条件 | 播放 |
|---|---|
| `truth_revealed >= 1` | dlg_feed_chat_records_high |
| `truth_revealed == 0` | dlg_feed_chat_records_low |

实现：对话系统求值 `dialogues.json` 的 `variants`（条件数组 + dialogue_id），按序取第一个满足的。**只按条件选文本，禁止程序生成/拼改对话内容**。

## 5. 获得与去重

1. 获得来源只有两个：物体步骤 `grants`、对话 `on_complete_grants`（事件效果 `grant_content` 同理）。
2. 按 content_id 去重：已获得不再入账、不再弹 toast。
3. 获得时：toast 提示（材料名 + 类型，docs/12 §8），写入 `contents_obtained`，自动存档。
4. 话题获得同理（入 topics_unlocked，toast"新话题解锁"）。

## 6. 特例：U盘（work_usb）

- U盘**不通过投喂列表投喂**：获得后在 AI 界面出现"使用 U 盘"话题入口（topic_usb，由事件解锁）。
- 话题对话流程即 U 盘的使用与投喂流程：对话完成时 `work_usb` 同步标记为已投喂（状态联动，二者关联 ID 见 docs/story 第一阶段清单）。
- `completeness_bonus = 0`（阶段转换时统一校正，D06）。

## 7. 对外接口

| 接口 | 说明 |
|---|---|
| `grant_content(ids: Array[String])` | 唯一发放入口（去重 + toast + 存档） |
| `content_obtained(content_id)` / `content_fed(content_id)` 信号 | 上报 GameState |
