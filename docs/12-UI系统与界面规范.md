# 12 · UI 系统与界面规范

> 职责：定义全部界面组件的布局、交互与状态规则。UI 组件全部放 `scenes/ui/`（清单见 docs/01）。
> 原则：**组件复用**——同类需求一律用同一组件，禁止为单个剧情单独做一套 UI。

## 1. 对话框 UI（决策 D20）

| 说话者 | 位置 | 占位样式（P17） |
|---|---|---|
| 男主（protagonist） | 屏幕左下角 | 白色文本 |
| 女主/AI（ai） | 屏幕右上角 | 浅青色文本 |
| 提示文本（system） | 屏幕右上角（与女主同区域） | 灰色文本 |

- 无头像、无立绘、无角色名称标签；说话者切换时文本框位置与样式随之切换。
- **同一时刻只有一个说话者的文本在显示，禁止互相覆盖**。
- 单句播完按剧本流程自动消失或等待点击推进（对话播放规则见 docs/05 §3）。

## 2. 左下角功能 UI（bottom_panel）

| 项 | 规格 |
|---|---|
| 位置 | 游戏主场景左下角，常驻（俯视图/特写/AI 界面），不遮挡主要场景与交互物体 |
| 构成 | 三个入口：**退出到底图 / 投喂 / 话题**（三个独立按钮，小尺寸，不占主要画面） |
| 退出到底图 | 从当前特写退回上一层底图（区域特写→俯视图；电脑桌→女主房间；AI 界面→俯视图；**俯视图中该按钮隐藏**）。禁止误退到游戏初始界面、禁止跨级返回 |
| 投喂 | 展开投喂材料列表（docs/04 §2 规则：当前阶段+已收集+未投喂；投喂后移除；阶段清空） |
| 话题 | 展开话题列表（docs/05 §4 规则：当前阶段已解锁；未解锁不显示；可重复对话） |
| 列表展开 | 覆盖于场景之上的面板；打开期间底层禁点；关闭恢复进入前界面状态 |
| 实现优先级 | ①（本项目 UI 需求整理中的第一优先级组件） |

## 3. 全屏文本 UI（fulltext_ui）

| 项 | 规格 |
|---|---|
| 用途 | 剧情叙述、男主独白、调查结果、协议长文档（D17） |
| 布局 | 纯色底图（开发期深灰）铺满 1920×1080 + 居中/偏上文本区 |
| 文本区 | 一次显示一页（fulltexts.json 的一个 page）；文字较多自动换行，超出一屏拆为多页录入 |
| 退出按钮 | 末页显示"退出"按钮，点击关闭并返回**进入前的场景**（P15：非末页点击画面任意处翻页） |
| 翻页 | 逐页推进；多页文本不可一键跳过（协议阅读无快进要求，保持简单） |
| 模态 | 打开期间底层禁点 |

## 4. 居中是/否确认 UI（confirm_dialog）

| 项 | 规格 |
|---|---|
| 尺寸 | 约 600×400，屏幕居中，背景半透明暗化（P14） |
| 内容 | 提示文本 + 是/否两个按钮 |
| 变体 | truth 样式（红色、字体大一号，docs/05 §5）与不可选演出模式（D10）复用此组件的布局逻辑 |
| 模态 | 打开期间底层禁点 |
| 实现优先级 | ③ |

## 5. 密码输入 UI（puzzle_wheel）

| 项 | 规格 |
|---|---|
| 形态 | 四位数字轮盘锁（上下箭头调每位数字）+ 确认 + 取消 + 错误提示区 |
| 判定 | 四位全部对照 puzzles.json 的 answer |
| 反馈 | 正确 → sfx_puzzle_correct + 成功流程；错误 → sfx_puzzle_wrong + 提示，允许重试 |
| 可复用 | 组件通用（电脑/手账本/抽屉均可复用），本期只接入电脑（D15） |
| 实现优先级 | ④ |

## 6. 电脑桌面与文件浏览 UI（computer_ui）

| 项 | 规格 |
|---|---|
| 桌面 | 电脑屏幕画面（占位深色桌面）：开机键交互点、上锁交互点（谜题前）、手账本入口；密码完成后出现三个文件夹图标 |
| 文件夹 | 点击文件夹 → 文件列表/内容页（占位文本页），带返回桌面按钮 |
| 社交帐号特殊演出 | 聊天记录按剧本以消息条目方式呈现（"对话框位置变化"= 消息条目依次出现，位置错落），后接收 D10 红色演出 |
| 模态 | 文件浏览期间底层禁点 |
| 实现优先级 | ⑤ |

## 7. 手账本阅读 UI（diary_viewer）

| 项 | 规格 |
|---|---|
| 内容 | 日期 + 事件文本列表（puzzles.json diary_entries，六条，见 docs/08） |
| 翻页 | 可上下滚动/翻页查看全部条目 |
| 阶段解锁 | 本期全部条目一次性显示（"分阶段解锁页面"为预留能力，本期无此需求，不实现） |
| 实现优先级 | ⑤ |

## 8. 通用提示浮层（toast）

| 项 | 规格 |
|---|---|
| 用途 | 材料获取提示（材料名称+类型图标+获取提示）、新话题解锁、操作反馈（"已保存""暂时无法进入""暂时无法交互""条件尚未满足"） |
| 形态 | 屏幕上方/侧边小型浮层，自动消失（约 2 秒），多条排队依次显示 |
| 禁止 | 提示类信息禁止动用全屏文本 UI 或确认弹窗 |
| 实现优先级 | ② |

## 9. 全局 UI 程序规则

1. **弹窗时底层禁点**：任何弹窗/全屏 UI/列表打开期间，底层场景与左下角功能 UI 不响应输入。
2. **返回正确层级**：所有 UI 关闭后回到打开前的界面状态；"退出到底图"按 docs/03 §1 层级返回，禁止跨级。
3. **阶段切换清空**：投喂列表与话题列表每阶段清空重新生成（已投喂状态永久保留，D18）。
4. **投喂后移除**：投喂成功的材料立即从列表消失。
5. **话题可重复**：已完成话题可反复对话，无重复解锁。
6. **分辨率适配**：全 UI 用锚点布局，逻辑分辨率 1920×1080，禁止绝对坐标定位。
7. **占位原则**（D13）：开发期全部用色块/默认字体实现，美术素材后补不阻塞。

## 10. 实现优先级（来自 UI 需求整理，开发顺序）

1. 左下角功能 UI（含投喂/话题列表）
2. 通用提示浮层
3. 居中是/否确认 UI（含 truth 样式与不可选模式）
4. 密码输入 UI
5. 电脑桌面与文件浏览 UI、手账本阅读 UI
