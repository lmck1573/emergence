## 2. Autoload 清单（全项目仅此三个，禁止新增）

| Autoload | 职责 | 严禁 |
|---|---|---|
| `GameState` | 持有全部游戏状态（阶段/调查/获得/投喂/事件/选择/数值/区域/场景/设置）；提供状态查询接口；触发自动保存；状态变更后通知事件系统复查 | 存任何 UI 引用、任何玩法逻辑 |
| `EventBus` | 跨场景解耦信号总线（如 `content_fed(content_id)`、`topic_completed(topic_id)`、`event_completed(event_id)`、`region_unlocked(region_id)`） | 存状态、存节点引用 |
| `AudioManager` | 音效/BGM 播放接口 + 总开关状态 | 剧情判定、状态存储 |

`ContentDB`（**不是 Autoload**）：static 类，启动时加载并校验 `res://data/` 全部 JSON，向各系统提供只读查询。JSON 解析失败必须在启动时报错并指明文件与字段。

## 3. 根场景节点树（main.tscn）

```
├── Main (Node)
│   ├── SceneManager (Node)          # 探索场景与 AI 界面的容器，负责切换
│   │   └── (当前场景实例)
│   ├── UILayer (CanvasLayer)        # 左下角功能UI（常驻）、对话框、内容列表、选择UI、完整度显示、提示浮层
│   ├── EffectLayer (CanvasLayer)    # 演出层：黑屏闪现、红色滤镜（最上层之下）
│   └── TransitionOverlay (CanvasLayer)  # 全屏过渡（淡入淡出、红色淹没）
```

UI 组件场景（scenes/ui/）：

| 场景 | 用途（规范见 docs/12） |
|---|---|
| bottom_panel.tscn | 左下角功能 UI：退出到底图 / 投喂 / 话题 三入口 + 展开列表 |
| fulltext_ui.tscn | 全屏文本 UI：纯色底图 + 剧情文本 + 翻页 + 退出 |
| confirm_dialog.tscn | 居中是/否确认弹窗（约 600×400，背景暗化） |
| dialogue_box.tscn | 对话框（双位置：男主左下角 / 女主与提示右上角，按说话者切换样式，见 docs/12 D20） |
| content_list.tscn | 投喂材料列表（bottom_panel 展开） |
| choice_ui.tscn | 真相选择 UI（红色大字样式 + 不可选演出模式） |
| puzzle_wheel.tscn | 四位数字轮盘锁（密码输入） |
| diary_viewer.tscn | 手账本事件列表/阅读界面 |
| computer_ui.tscn | 电脑桌面与文件浏览界面 |
| toast.tscn | 通用提示浮层（材料获取/话题解锁/操作反馈） |

规则：
- UI 与场景**分层**，场景切换不销毁 UI。
- 演出指令（黑屏闪现等）由对话系统通过 EffectLayer 执行，场景自身不实现演出。
- 各特写场景必须可 F6 独立运行（无父上下文不崩溃；缺少数据时显示占位色块）。

## 4. 系统职责边界表（越界 = 返工）

| 系统 | 文档 | 唯一职责 | 对外接口（其他系统只允许调用这些） | 严禁 |
|---|---|---|---|---|
| 场景与调查 | docs/03 | 区域切换、物体点击、二级操作状态机、物体状态展示 | 信号 `object_investigated(object_id, step_id)`；方法 `refresh_region(region_id)` | 判定剧情条件、发放内容（只上报点击结果） |
| 内容与投喂 | docs/04 | 内容列表 UI、投喂流程、投喂状态 | 信号 `content_obtained(content_id)`、`content_fed(content_id)`；方法 `grant_content(ids)` | 播放对话（委托对话系统） |
| AI 对话 | docs/05 | 话题列表、对话播放、逐字/跳过、选择 UI、演出指令执行 | 信号 `topic_completed(topic_id)`、`choice_made(event_id, option)`；方法 `play_dialogue(dialogue_id)` | 判定条件、修改数值 |
| 剧情事件 | docs/06 | 条件求值、事件触发排序、效果执行 | 信号 `event_completed(event_id)`；方法 `check_events()`（GameState 在状态变更后调用） | 直接操作场景节点（通过效果指令间接驱动） |
| 数值 | docs/07 | truth_revealed 与人格完整度的读写与显示 | `add_truth(n)`、`get_truth() -> int`、`get_completeness() -> float`、信号 `completeness_changed(value)` | 阻断任何阶段推进（只记录） |
| 解谜 | docs/08 | 谜题 UI、输入判定、完成状态 | 信号 `puzzle_completed(puzzle_id)` | 判定事件条件（只上报完成） |
| 存档 | docs/09 | 状态快照/恢复/版本迁移 | `save()`、`load_save()`、`has_save()` | 任何玩法逻辑 |
| 音频 | docs/10 | `play_cue(cue_id)`、`set_muted(bool)` | — | 剧情判定 |

## 5. 数据流（一次典型点击）

```
玩家点击物体
  → 场景系统上报 object_investigated(object_id, step_id)
  → GameState 更新调查状态
  → GameState 询问 ContentDB：该步骤是否配置了 grants
      → 是 → 内容系统 grant_content(ids) → content_obtained 信号
  → GameState 调用 事件系统 check_events()
      → 满足条件的事件按优先级入队执行（播放对话/解锁区域/修改数值…）
  → 事件队列清空后 → 存档系统 save()
  → 场景系统 refresh_region() 更新显示
```

**要点**：状态变更永远是单向的（操作 → GameState → 事件检查 → 效果），任何系统不得绕过 GameState 直接改其他系统的状态。

## 6. 分辨率与坐标规范

- 逻辑画布 1920 × 1080（`canvas_items` 拉伸 + `expand` 宽高比，已在 project.godot 配置）。
- 探索场景 960 × 960，居中偏上（左上角约 (480, 60)）。
- 物体点击区域用**相对场景原点**的矩形（`x, y, w, h`），存于 objects.json，禁止写死屏幕绝对坐标。
- UI 元素锚点布局，返回按钮固定左下角，存档按钮固定右下角（AI 界面）。
- 开发期占位：场景背景 = 纯色矩形 + 区域名 Label；交互物体 = 半透明色块 + 物体名 Label + 可视化点击框（可通过调试开关显示/隐藏所有点击区域）。
