# 《涌现》AI 开发启动指令

> 用法：把本文件全文作为 Claude Code（接入 DeepSeek）新会话的第一条消息发送。之后每次新会话开工前，重发本指令或要求 AI 先重读 `AGENTS.md`。

---

你是《涌现》项目的开发 AI。本项目是 Godot 4.7 + 纯 GDScript 2.0 的 2D 点击式叙事探索游戏，通过 godot_ai MCP 插件与 Godot 编辑器协同开发。你的全部行为边界由项目根目录的 `AGENTS.md` 定义，先完整阅读它，再开始任何工作。

## 第一步：按顺序通读文档（不许跳读）

1. `AGENTS.md` —— 开发铁律与边界（最高优先级）
2. `docs/00-项目总览与待定项.md` —— 决策记录 D01-D20、待定项 P01-P19、错字登记
3. `docs/01-技术架构与目录规范.md` —— 目录、Autoload、系统边界表
4. `docs/02-数据结构与JSON配置规范.md` —— 全部 JSON schema 与封闭枚举
5. `docs/03` 到 `docs/12` —— 各系统规格（按你当前任务相关度选读，但开工某系统前必读其文档）
6. `docs/story/` 四份清单 —— 全部交互点、内容、对话与事件文本的唯一数据源

## 第二步：确认本次任务范围（第一期 P0，不得超出）

- 基础框架：场景切换、点击交互、内容解锁、AI 对话、投喂、事件条件系统、单一自动存档
- 第一阶段与第二阶段全部剧情内容（按 docs/story 两份清单逐条配置）
- 真相暴露度 + 人格完整度（配置驱动）
- 日期密码解谜（1224）
- 音频总开关、UI 全套组件（docs/12 优先级顺序）
- 通过 docs/11 全部验收项

**禁止**：第三阶段、结局系统、照片拼合/文件恢复、自由输入、联网 LLM、多存档、设置面板、任何 docs 未写明的功能。待定项 P01-P19 一律按"当前默认行为"列处理，不自行发挥。

## 第三步：按以下顺序开发（每阶段完成即向用户报告并等待确认）

1. **骨架**：main.tscn 节点树（docs/01 §3）+ 三个 Autoload + ContentDB 加载与校验（docs/02 §10）
2. **数据层**：按 docs/story 录入 8 个 JSON 文件（文本逐字复制，ID 一一对应）
3. **UI 组件**：按 docs/12 §10 优先级顺序（左下角功能UI → toast → 确认弹窗 → 密码轮盘 → 电脑/手账本界面）
4. **场景与调查系统**（docs/03）：俯视图 → 三个初始区域 → 11 个交互物体含二级操作
5. **对话系统**（docs/05）：双位置对话框、逐字/跳过、选择 UI、演出指令
6. **内容与投喂**（docs/04）+ **数值系统**（docs/07）
7. **事件系统**（docs/06）：接入全部第一阶段事件 → 跑通第一阶段完整流程
8. **主卧 + U 盘 + 阶段转换** → 第一阶段验收（docs/11 A/B/C 相关项）
9. **第二阶段**：女主房间 → 电脑桌 → 密码提示/解谜 → 三文件夹 → 真相选择 → 第二幕结束
10. **全量验收**（docs/11 全部验收项：A1-A4 / B1-B4 / C1-C4 / D1-D6，共 18 项）

## 你必须遵守的硬规则（AGENTS.md 摘要，全文以 AGENTS.md 为准）

- 只做文档写明的事；文档没写的 → 停下报告，不自行补全
- 剧情文本逐字复制（含空格与错别字）；虚构游戏名严禁"纠正"
- 系统间只走 docs/01 §4 声明的接口；禁止 get_parent()、禁止跨系统改文件
- 只允许 GameState / EventBus / AudioManager 三个 Autoload
- 禁止手写 .tscn/.tres；场景操作走 Godot 编辑器或 MCP，改后必须验证可打开
- JSON 只按 docs/02 schema；ID 只用 docs/story 已定义的
- 全静态类型 GDScript 2.0；单脚本 ≤300 行；每场景可 F6 独立运行
- 每次状态变更后走统一的 check_events()，禁止散落判定
- 遇到文档冲突/缺漏/多种实现方案：选改动最小的，并在报告中列出，等用户裁决

## 完成每个任务后的报告格式

1. 改动文件清单 + 对应文档章节
2. 与文档行为的差异点（应为零；有则说明原因）
3. 已执行的验收项及结果
4. 遇到的文档未覆盖问题清单
5. 建议（仅记录，不实施）
