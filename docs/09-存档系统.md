# 09 · 存档系统

> 职责：游戏状态的快照与恢复。**不含任何玩法逻辑**。

## 1. 存档方式（锁定）

- **单一自动存档**，文件 `user://save_data.json`（UTF-8）。
- 无多存档槽、无手动存档槽、无导出导入。
- AI 交互界面右下角存档按钮：点击立即保存 + toast"已保存"（D09，无二次确认）。
- 存档带 `save_version` 字段（初始 1）。读取时版本不匹配：将旧文件改名为 `save_data.bak` 保留，新建新档，并在日志中记录（不做复杂数据迁移，本期只有 v1）。

## 2. 保存的全部状态（缺一 = 实现错误）

| 字段 | 内容 |
|---|---|
| `save_version` | 存档版本号 |
| `phase` | 当前阶段（1/2） |
| `current_scene` | 当前场景 ID（恢复位置） |
| `objects` | 每个物体的步骤完成进度（object_id → 已完成 step 列表） |
| `contents_obtained` | 已获得内容 ID 列表 |
| `contents_fed` | 已投喂内容 ID 列表（**跨阶段保留**，D18） |
| `topics_unlocked` | 已解锁话题 ID 列表 |
| `topics_completed` | 已完成对话的话题 ID 列表 |
| `events_completed` | 已完成事件 ID 列表 |
| `puzzles` | 谜题状态（未解锁/可解/已完成） |
| `player_choices` | 事件 ID → 选择结果（`"yes"`/`"no"`） |
| `truth_revealed` | 真相暴露度整数 |
| `completeness` | 人格完整度浮点 |
| `regions_unlocked` | 已解锁区域 ID 列表 |
| `opening_read` | 两份开场协议各自已读状态 |
| `flags` | 自由标记字典（阶段转换等） |
| `settings` | 音频开关状态 |

**不保存**（已删除/不存在的机制，相关字段禁止出现）：21 天倒计时、每日任务、当前天数、当前结局。

## 3. 自动保存时机（每个时机都在状态更新**之后**）

1. 首次调查获得新内容
2. 物体步骤完成（多步物体每步都保存）
3. 投喂结算完成
4. 话题对话完成
5. 解谜成功
6. 玩家做出关键选择（真相选择）
7. 剧情事件完成
8. 新区域解锁
9. 阶段转换完成
10. 手动点击存档按钮

## 4. 恢复规则

| 场景 | 行为 |
|---|---|
| 启动有档 | 直接恢复：场景、阶段、全部状态；AI 界面显示的完整度立即正确 |
| 启动无档 | 从开场（AI 界面 + 眼睛动画 + 两份协议）开始 |
| 事件播放中途退出 | 该事件视为未完成，重进后**从事件开头重播**（宁可重播不可跳过） |
| 阶段转换中途退出 | 转换未完成 → 回到转换前状态，重进后重新触发转换事件 |
| 恢复后界面 | 投喂/话题列表按当前阶段重建（只含未投喂材料/可用话题） |

## 5. 对外接口

| 接口 | 说明 |
|---|---|
| `save()` | 序列化 GameState 全部字段写盘 |
| `load_save() -> bool` | 读取并注入状态 |
| `has_save() -> bool` | 启动判断用 |

## 6. 自检清单

- [ ] 退出重进：内容、投喂、谜题、事件、选择、数值、场景全部一致
- [ ] 事件播放中途杀进程，重进该事件从头重播
- [ ] 存档文件不包含已删除机制的字段
- [ ] 版本不匹配时旧档备份为 .bak 并新建
