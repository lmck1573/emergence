# 05 · AI 对话与话题系统

> **职责：** AI 交互界面的展示、话题列表、对话播放（逐字显示 / 跳过）、选择 UI、剧情演出指令的执行。
>
> **核心原则：** 一段完整对话对应一个 `dialogue_id`，内部包含多条按顺序播放的台词；每条台词独立指定显示类型。交互点、话题系统或剧情事件触发对话时，只需传入 `dialogue_id`。
>
> **系统边界：** 本系统不负责剧情条件判定、不直接修改游戏数值、不决定何时触发剧情。条件判定由外部剧情 / 事件系统负责，数值修改由外部效果执行系统负责。本系统接收对话 ID、播放对应内容，并通过信号通知其他系统播放结果。
>
> **编辑方式：** Godot 原生 Inspector + GDScript + Resource（`.tres`）。不开发独立编辑器，不要求为单条台词或每段剧情编写专用代码。

## 1. AI 交互界面构成

```text
┌────────────────────────────────────────────┐
│                                            │
│             [AI 形象区]                    │
│          眼睛 / 女主形象                    │
│          含眨眼动画                         │
│                                            │
│ [人格完整度百分比显示]                      │
│                                            │
│             [AI / 女主台词框]               │ ← 右上方
│                                            │
│                                            │
│ [男主台词框]                               │ ← 左下方
│                                            │
│ [退出到底图 / 投喂 / 话题]                 │ ← 左下方功能 UI
│                              [存档][音频]  │ ← 右下角
└────────────────────────────────────────────┘
```

### 1.1 AI 形象状态

| 状态 | 时机 |
|---|---|
| 眼睛闭合 / 睁开，循环眨眼 | 第一阶段全程 |
| 眼睛静止 → 后退 → 显示脸部 → 显示上半身 | 第一阶段结束演出 |
| 上半身形象，眨眼循环 | 第二阶段全程 |
| 上半身微笑表情 | 根据 `portrait_smile` 演出指令切换 |

开发期全部使用色块 / 简单形状占位：眼睛使用椭圆，女主使用色块人形，眨眼通过缩放动画模拟。

AI 形象状态由演出指令控制，不由对话 UI 根据当前文本自行推断。

### 1.2 人格完整度

- 显示当前人格完整度百分比。
- 数值由外部游戏状态系统提供，本系统只负责显示。
- 本系统不计算、不增加、不减少人格完整度。

### 1.3 UI 组织

建议使用 Godot 原生场景节点：

## 2. 对话数据与显示规则（决策 D20）

### 2.1 对话数据结构

一段完整对话对应一个 `DialogueData` 资源，拥有唯一的 `dialogue_id`，内部包含多条有序台词。

例如：

```text
dialogue_id: computer_first_visit

lines:
  0. protagonist: 她以前总是在这里写东西……
  1. system: 电脑屏幕上留有一份未保存的文件。
  2. ai: 你终于发现了。
  3. protagonist: ……
```

以上四句属于同一段对话，不需要为每句台词单独设置 ID。

**数据组织规则：**

- 一个 `dialogue_id` 对应一段完整对话。
- 一段对话包含任意数量的 `DialogueLine`。
- 台词按照数组顺序播放，使用当前数组索引推进。
- 每条台词独立设置显示类型和文本内容。
- 选择分支、演出指令等作为对话结构中的可选配置，不需要拆分普通台词的 ID。

### 2.2 Godot 编辑方式

使用 Godot 原生 `Resource`：

- `DialogueData`：整段对话。
- `DialogueLine`：单条台词。
- `DialogueChoice`：选择 UI 配置。
- `DialogueCommand`：演出指令配置。

在 Inspector 中创建和编辑 `.tres` 资源，台词通过数组添加、排序和修改。

本系统不使用独立对话编辑器，也不要求为每句台词编写专用脚本。

**数据来源调整：** 对话内容以 Godot Resource 为权威来源，不再要求所有文本必须存储在 `dialogues.json` 中。外部剧情 / 事件系统仍通过 `dialogue_id` 调用对话，不依赖具体资源文件路径。

### 2.3 对话框显示类型

| 显示类型 | 位置 | 样式 |
|---|---|---|
| `protagonist` | 屏幕左下角 | 白色文本（P17 占位） |
| `ai` | 屏幕右上角 | 浅青色文本（P17 占位） |
| `system` | 屏幕右上角 | 灰色文本 |

规则：

- 无头像、无立绘、无角色名称标签。
- 每条台词通过 `display_type` 指定显示类型。
- 对话管理器根据 `display_type` 将文本交给对应的 UI 控件。
- 同一时刻只显示一个说话者的文本；切换类型时，先隐藏上一控件，再显示当前控件。
- 禁止两个文本框同时显示或互相覆盖。
- 同一段对话可以自由混合不同显示类型的台词。
- 第一阶段 AI 的机械说话风格（如 `"喜欢 什么 电影？"`）属于文本内容，排版必须原样保留空格，不得自动清理或合并空格。

### 2.4 单条台词的可配置字段

每条 `DialogueLine` 至少包含：

| 字段 | 说明 |
|---|---|
| `display_type` | `protagonist` / `ai` / `system` |
| `text` | 当前台词的完整文本 |
| `advance_mode` | 点击推进 / 自动推进 / 不自动推进 |
| `commands` | 可选的演出指令列表 |

显示类型默认值可根据常用场景预设，但具体台词可以在 Inspector 中单独修改。

不要求每句台词配置独立 ID，也不要求每句台词编写独立逻辑。

## 3. 对话触发与播放

### 3.1 对话触发

对话系统不负责判断触发条件，只提供统一的调用入口：

```gdscript
DialogueManager.play_dialogue("computer_first_visit")
```

调用方只需要提供对话 ID。

支持以下触发来源：

1. **交互点触发：** 玩家点击电脑、抽屉、照片等物品，交互点脚本调用对应的对话 ID。
2. **话题触发：** 玩家点击已解锁的话题，话题系统调用该话题关联的对话 ID。
3. **投喂触发：** 投喂系统完成操作后，由外部事件系统判断是否触发后续对话。
4. **剧情事件触发：** 外部剧情 / 事件系统满足条件后，调用指定对话 ID。

一个交互点可以根据外部剧情状态关联不同的对话 ID。例如：

| 触发来源 | 传入的对话 ID |
|---|---|
| 第一次点击电脑 | `computer_first_visit` |
| 获得新线索后点击电脑 | `computer_new_clue` |
| 点击已解锁话题 | `topic_computer` |
| 投喂文件后触发 | `usb_file_response` |

这些对应关系由交互点或剧情 / 事件系统配置。对话管理器不自行判断哪个 ID 应该被触发。

### 3.2 对话播放规则

1. 收到有效的 `dialogue_id` 后，加载对应的 `DialogueData`。
2. 如果由剧情事件自动触发，先自动切入 AI 交互界面，再开始播放。
3. 从第一条台词开始，按数组顺序逐条播放。
4. 默认使用打字机效果。
5. 玩家第一次点击：立即显示当前整句文本，跳过逐字效果。
6. 当前整句已经显示后，玩家再次点击：进入下一条台词。
7. 切换台词时，根据当前台词的 `display_type` 显示对应 UI 控件。
8. 所有台词播放完毕后，检查是否有选择 UI；有则进入选择流程，无则结束对话。
9. 对话结束后执行已配置的结束事件，并发出对应信号。

### 3.3 对话期间的输入管理

- 对话播放期间，屏蔽左下角功能 UI 的输入。
- 对话播放期间，屏蔽底层场景点击。
- 对话推进只响应当前对话允许的输入。
- 对话一旦开始必须播完，不提供整段对话跳过或中途退出功能。
- 跳过仅指跳过当前台词的逐字显示效果。
- 对话由事件自动触发时，播放完毕后停留在 AI 交互界面，不自动返回探索场景。

### 3.4 对话结束事件

`DialogueData` 可以配置可选的 `on_complete` 事件引用，但事件的实际执行由外部事件系统负责。

本系统只负责在对话正常结束时发出完成信号，并提供对应的对话 ID。外部系统根据 ID 或预先配置的映射执行后续操作。

禁止将剧情条件判断、材料发放、数值修改等逻辑直接写入对话播放代码。

## 4. 话题列表（决策 D19）

### 4.1 入口与数据来源

入口为左下角功能 UI 的「话题」按钮。

话题列表由话题系统负责展示；话题的解锁状态与所属阶段由外部游戏状态 / 剧情系统提供。

每个话题至少包含：

- `topic_id`
- 话题显示名称
- 所属阶段
- 解锁状态
- 对应的 `dialogue_id`，允许为空

话题列表根据外部提供的状态筛选，本系统不负责判定解锁条件。

### 4.2 列表显示规则

只显示同时满足以下条件的话题：

- 属于当前阶段。
- 已解锁。
- `dialogue_id` 不为空，且存在有效的对话配置。

无对话配置的话题不显示（D14）。

**无对话话题的完成标记：** 若某话题被解锁时不需要玩家操作，且其「已完成」状态用于其他事件条件，则由外部剧情 / 事件系统在解锁时自动标记完成（P19，例如「锁上的电脑」话题）。不要求玩家进入话题列表操作。

### 4.3 重复使用

- 已完成的话题可以反复点击、反复播放其关联对话。
- 重复播放仅重播对话内容。
- 重复播放不重复发放材料、不重复增加数值、不重复执行一次性剧情事件。
- 一次性效果由外部事件系统通过完成记录或幂等检查保证，不依赖 UI 是否重复打开。

### 4.4 阶段切换

- 阶段切换由外部剧情 / 阶段系统负责。
- 话题列表读取当前阶段与新阶段的解锁状态后刷新。
- 旧阶段话题不再显示，新阶段话题按解锁状态重新生成。
- 对话系统不自行修改阶段状态。
- 打开话题列表期间，底层场景不可点击；关闭列表后恢复原有交互状态。

## 5. 选择 UI

### 5.1 样式

| 样式 | 用途 | 规格 |
|---|---|---|
| `normal` | 通用是 / 否确认 | 居中约 600×400，背景暗化（docs/12） |
| `truth` | 真相选择 | 红色、字体大一号，「是 / 否」两项 |
| `truth` + `selectable=false` | 不可选演出（D10） | UI 照常显示，但不响应点击；显示 `locked_show_duration` 秒后被 `red_flood` 演出覆盖并消失 |

选择 UI 的样式、选项文本、可选状态、显示时长与分支对话引用由 Inspector 中的选择配置提供。

### 5.2 选择结果处理

- 玩家选择后，选择 UI 向对话 / 事件系统提交 `event_id` 与选项值。
- 选择记录由外部事件 / 存档系统保存，写入 `player_choice`。
- 选择完成后，通过预先配置的 `branch_dialogue_id` 播放对应分支对话。
- 选择「是」时，由外部效果执行系统处理 `add_truth_1`（docs/07）；选择「否」只记录结果。
- 同一事件的选择只结算一次。
- 已经结算过的事件再次触发时，读取历史选择结果，不显示可重新选择的 UI。
- 上述历史结果检查与数值结算不由对话 UI 自行实现，由外部事件 / 存档系统负责，并将处理结果传回本系统。

### 5.3 不可选演出模式

当选择配置为 `truth` 且 `selectable=false` 时：

- 正常显示红色真相选择 UI。
- 所有选项不可点击。
- 不允许键盘、鼠标或其他输入改变选择结果。
- 按配置的 `locked_show_duration` 等待。
- 等待结束后触发 `red_flood` 演出。
- 演出覆盖选择 UI 后将其关闭。
- 该流程不生成玩家选择结果，也不发出 `choice_made` 信号。

## 6. 演出指令执行

对话中可以配置演出指令。指令采用封闭枚举，只执行预先定义的类型，不允许通过文本直接执行任意代码（见 docs/02 §7）。

| 指令 | 效果 |
|---|---|
| `black_flash` | 全屏变黑 0.3 秒后恢复，由 `EffectLayer` 实现 |
| `red_heartbeat` | 红色滤镜渐入并播放心跳音效，持续 3 秒 |
| `tinnitus` | 播放耳鸣音效，可与红色滤镜叠加 |
| `red_flood` | 红色从屏幕边缘淹没全屏，停留后逐渐减退，全程约 3 秒 |
| `portrait_*` | 切换 AI 形象区显示状态，如眼睛、脸部、上半身、微笑表情 |

### 6.1 执行规则

- 演出指令由对话配置引用，并由演出执行模块负责具体表现。
- 对话系统负责在正确的台词 / 选择节点发起演出。
- 演出执行期间，暂停对话推进。
- 演出完成后，恢复原有播放状态。
- 支持预先定义的演出叠加，例如 `tinnitus` 与红色滤镜同时执行。
- 不允许重复点击、自动推进或其他输入绕过尚未完成的演出。
- 演出执行失败或资源缺失时，应输出开发期警告，不能永久锁死对话推进状态。

## 7. 对外接口

| 接口 | 类型 | 职责 |
|---|---|---|
| `play_dialogue(dialogue_id: String)` | 方法 | 播放指定 ID 对应的完整对话 |
| `dialogue_started(dialogue_id: String)` | 信号 | 对话开始时发出 |
| `dialogue_finished(dialogue_id: String)` | 信号 | 对话正常结束时发出 |
| `topic_completed(topic_id: String)` | 信号 | 话题关联的对话首次完成时发出 |
| `choice_made(event_id: String, option: String)` | 信号 | 玩家完成有效选择时发出 |
| `command_started(command_id: String)` | 信号 | 演出指令开始时发出 |
| `command_finished(command_id: String)` | 信号 | 演出指令完成时发出 |

### 7.1 接口约定

- `play_dialogue` 只接收 `dialogue_id`，不接收整段台词文本。
- 对话 ID 必须能映射到有效的 `DialogueData` 资源。
- 同一时刻只允许一段普通对话播放；新请求到达时，按项目统一规则拒绝或排队，不允许静默覆盖正在播放的对话。
- `dialogue_finished` 仅在正常播放完成后发出；如果未来增加强制终止机制，需要定义独立的终止信号。
- `topic_completed` 只在话题关联的对话首次正常完成时发出。重复播放不重复发出。
- `choice_made` 只针对真实有效的玩家选择发出；不可选演出不触发此信号。
- 本系统发出信号，不直接修改人格完整度、真相点数、材料或阶段状态。

## 8. 自检清单

### 对话数据与播放

- [ ] 每段对话具有唯一 `dialogue_id`。
- [ ] 一段对话可以包含任意数量的台词，不要求每句台词有独立 ID。
- [ ] 台词顺序由数组顺序决定。
- [ ] 每条台词可在 Inspector 中独立设置显示类型。
- [ ] 缺失或无效的对话 ID 会输出警告，不导致游戏崩溃。
- [ ] 对话资源可直接通过 Godot 原生 Inspector 创建、编辑和排序。

### 对话框与输入

- [ ] 男主台词显示在左下方，AI 台词显示在右上方。
- [ ] 系统提示显示在右上方，使用灰色文本。
- [ ] 同一时刻只显示一个文本控件，不发生重叠。
- [ ] 逐字显示可点击跳过；跳过后再次点击进入下一句。
- [ ] 对话播放中左下角功能 UI 与底层场景点击全部失效。
- [ ] 对话播放期间不允许整段跳过或中途退出。
- [ ] 演出执行期间暂停推进，演出结束后恢复。

### 触发与话题

- [ ] 交互点可通过对话 ID 触发对应对话。
- [ ] 外部剧情事件满足条件后，可通过对话 ID 触发对应对话。
- [ ] 同一交互点可根据外部剧情状态触发不同对话。
- [ ] 话题列表只显示当前阶段、已解锁且具有有效对话配置的话题。
- [ ] 无对话配置但需要自动完成的话题，由外部系统负责标记完成。
- [ ] 话题重复对话不重复发放内容、不重复触发一次性效果。
- [ ] 阶段切换后，话题列表按照新阶段状态刷新。

### 选择与演出

- [ ] 通用确认 UI 与真相选择 UI 使用各自的样式。
- [ ] 不可选真相演出无法通过任何输入改变结果。
- [ ] 不可选演出在规定时间后触发 `red_flood` 并消失。
- [ ] 选择结果正确记录并写入存档。
- [ ] 「是」只通过外部效果系统增加一次真相点数；「否」只记录结果。
- [ ] 同一事件重复触发时恢复历史选择，不允许二次结算。
- [ ] 演出指令结束后能够恢复对话，不出现永久锁死。

### 系统边界

- [ ] 对话系统不自行判断剧情触发条件。
- [ ] 对话系统不直接修改人格完整度、真相点数、材料或阶段状态。
- [ ] 所有剧情触发条件由外部剧情 / 事件系统管理。
- [ ] 所有一次性奖励与数值效果由外部效果执行系统管理。
- [ ] 对话系统只负责按 ID 找到内容、播放文本、执行已配置的表现指令，并发出播放结果信号。
